# Сашок стишок 3.2 — профили и синхронизация

Версия 3.2 построена поверх версии 3.1 с сессиями чтения.

## Что добавлено
- Профиль для каждого пользователя.
- Регистрация и вход по email + пароль.
- Имя профиля и аватар с первой буквой имени.
- Облачное хранение библиотеки, заметок, целей, календаря, времени чтения и истории сессий.
- Синхронизация между устройствами через Supabase.
- Локальное хранение остаётся резервной копией браузера.
- При входе на новом устройстве облачные данные профиля загружаются автоматически.
- Если у профиля ещё нет облачных данных, текущие локальные данные устройства сохраняются в профиль.

## Настройка Supabase

GitHub Pages не предоставляет базу данных и аккаунты, поэтому синхронизация сделана через Supabase.

1. Создай проект в Supabase.
2. Открой **SQL Editor → New query**.
3. Вставь содержимое `supabase.sql` и нажми **Run**.
4. Открой `supabase-config.js` и укажи Project URL и публичный anon/publishable key.
5. Загрузи содержимое архива в GitHub Pages.

**Важно:** не вставляй `service_role`/secret key во фронтенд. Для браузера нужен только публичный anon/publishable key, а доступ защищается RLS-политиками из `supabase.sql`.

## Email confirmation

Для теста можно отключить обязательное подтверждение email в настройках Auth. Для публичного проекта лучше оставить подтверждение включённым.

## Как работает синхронизация

Изменения сначала сохраняются в браузере, затем с небольшой задержкой отправляются в таблицу `user_data` конкретного пользователя. При входе приложение загружает данные из облака. Один аккаунт = одна общая библиотека на всех устройствах.

## Что синхронизируется

- книги и прогресс;
- заметки;
- годовая цель;
- календарь чтения;
- общее время чтения;
- история сессий чтения.

Поиск книг по-прежнему использует Open Library API.
